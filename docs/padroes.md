# Convenções e padrões de código

## Roteamento (file-based)

TanStack Router. Cada `.tsx` em `src/routes/` é uma rota. Regras (ver
[src/routes/README.md](../../src/routes/README.md)):

| Arquivo                        | URL                                                                 |
| ------------------------------ | ------------------------------------------------------------------- |
| `index.tsx`                    | `/`                                                                 |
| `auth.tsx`                     | `/auth`                                                             |
| `_authenticated/route.tsx`     | layout da área logada (prefixo `_` = pathless)                      |
| `_authenticated/dashboard.tsx` | `/dashboard`                                                        |
| `workouts.session.$id.tsx`     | `/workouts/session/:id` (segmentos por ponto, `$` = param dinâmico) |

- **Não** criar `src/pages/`, `app/layout.tsx` etc. (convenções de Next/Remix).
- `routeTree.gen.ts` é **auto-gerado** pelo plugin — nunca editar à mão.
- Toda rota exporta `export const Route = createFileRoute("...")({ ... })`.
- `head: () => ({ meta: [...] })` define `<title>`/SEO por rota. Títulos seguem o
  padrão `"<Página> — Forja"`.

## Imports e aliases

- Import absoluto `@/` para tudo em `src` (ex.: `import { supabase } from "@/integrations/supabase/client"`).
- Client Supabase sempre importado como:
  `import { supabase } from "@/integrations/supabase/client";`

## Padrão de tela

Quase toda rota logada segue este esqueleto (ver qualquer arquivo em `_authenticated/`):

```tsx
export const Route = createFileRoute("/_authenticated/x")({ head: () => ({...}), component: XPage });

function XPage() {
  const qc = useQueryClient();
  const data = useQuery({ queryKey: [...], queryFn: async () => { /* supabase */ } });
  const mut = useMutation({ mutationFn: async () => {...}, onSuccess: () => qc.invalidateQueries(...) });
  return (
    <>
      <PageHeader title="..." description="..." action={<.../>} />
      <PageBody>{/* Cards, listas */}</PageBody>
    </>
  );
}
```

- **Layout comum:** `PageHeader` + `PageBody` de [components/page-header.tsx](../../src/components/page-header.tsx).
- **UI:** componentes de `@/components/ui/*` (Card, Button, Input, Dialog, Select, Tabs...).
- **Diálogos de adicionar** (exercício, alimento, ingrediente) são componentes
  locais no mesmo arquivo da rota, com `useQuery({ enabled: open })` para só buscar
  quando abertos.

## Chaves de cache do React Query

Sem factory central — as `queryKey` são arrays literais definidos por tela. Chaves
compartilhadas entre telas (invalidação cruzada):

- `["profile"]` — usada em dashboard, diet, profile.
- `["food_log", date]` — diário; invalidada ao adicionar via receita.
- `["history"]`, `["recent_sessions"]` — sessões de treino.
- `["templates"]`, `["template", id]`, `["template_items", id]`.
- `["weights_all"]`, `["weights_30"]`, `["measurements"]`, `["progress_photos"]`.
- `["recipes"]`, `["recipe", id]`, `["recipe_items", id]`.

Ao criar mutação, lembrar de invalidar **todas** as chaves afetadas (ex.: registrar
peso invalida `weights_all` **e** `weights_30`).

## Números vindos do banco

Colunas `NUMERIC` do Postgres chegam como **string** no JS. O código faz `Number(...)`
defensivo em quase todo cálculo (ex.: `Number(f.kcal) * factor`). Manter esse hábito.

## Estilo e tokens

- Cores/gradientes por **CSS variables** (`var(--primary)`, `var(--gradient-primary)`,
  `var(--shadow-soft)`) definidas em [src/styles.css](../../src/styles.css). Preferir
  tokens a cores hardcoded.
- Classes utilitárias Tailwind inline; `cn()` para merge condicional.
- Mobile-first: sidebar em `md:`, bottom-nav no mobile (ver `_authenticated/route.tsx`).

## Idioma

- **UI e textos: português (pt-BR).** Comentários de código e nomes de identificadores:
  inglês. Nomes de tabelas/colunas: inglês.

## Anti-padrões observados (tolerados no projeto)

- `void Component;` no fim de alguns arquivos para suprimir avisos de import não
  usado (ex.: [diet.tsx](../../src/routes/_authenticated/diet.tsx) linha final,
  [workouts.session.$id.tsx](../../src/routes/_authenticated/workouts.session.$id.tsx)).
  `noUnusedLocals`/`noUnusedParameters` estão `false` no tsconfig.
- Alguns cálculos de exibição duplicados entre telas (ex.: soma de macros aparece
  em dashboard e diet). Não há util compartilhado para isso. ⚠️ candidato a refatoração.
